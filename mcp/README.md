# Mora MCP

Mora MCP работает по стандартному Model Context Protocol и не привязан к модели или производителю AI-клиента. Сервер использует официальный Python SDK; финансовые операции проверяет тот же Swift-модуль, что и приложение.

## Локальное подключение

После выполнения `zsh scripts/setup-mcp.sh` доступны:

- Сервер: mcp/server.py.
- Локальное окружение: .venv.
- Конфигурация подключения: mcp/client-config.json (создается локально и не хранится в Git).
- Промпт для CSV: Prompts/mora-csv.md.
- Промпт для агента: Prompts/mora-mcp.md, также доступен как MCP prompt mora_finance_assistant.

В Mora откройте «Настройки → AI-помощник»: там можно скопировать CSV-промпт с актуальными счетами и категориями либо инструкцию для подключенного MCP-агента.

Укажите в своем AI-клиенте новый MCP-сервер с локальным запуском (stdio). Команда и аргументы находятся в client-config.json; этот файл можно использовать в клиентах с форматом mcpServers. Для клиентов с другой формой настройки перенесите те же command и args. Подключение не добавлено автоматически в какой-либо конкретный AI-клиент.

После подключения можно попросить:
«Запиши сегодняшние расходы: кофе 320 RSD с моего счета в динарах и продукты 1840 RSD с того же счета».
Агент узнает реальные названия счетов, проверит операции и запишет их. Если пользователь не указал или не подтвердил счет для этих операций, агент спросит его, даже когда есть только один счет в нужной валюте. Валюта и номер карты без подтвержденной связи со счетом не разрешают автоматический выбор. Остальные неизвестные финансовые факты тоже требуют уточнения.

Приложение подхватывает внешние изменения примерно за 2 секунды. Оно не должно оставаться открытым для работы MCP. После обновления сборки перезапустите Mora, чтобы включилась синхронизация с MCP.

Пока открыта старая Mora без поддержки совместной записи, MCP разрешает чтение и предпросмотр, но отклоняет запись с просьбой перезапустить обновленную версию. Это защищает базу от старой GUI, которая еще не знает о блокировках MCP.

## Установка в новом месте

Нужен macOS 14+, Python 3.10+ и Swift 6 для сборки. В каталоге проекта:
~~~sh
zsh scripts/setup-mcp.sh
~~~
Скрипт устанавливает MCP SDK только в окружение проекта, собирает приложение и создает конфигурацию с актуальными абсолютными путями. macOS-приложение по-прежнему не зависит от Python; он нужен только MCP.

## Инструменты

| Инструмент | Действие |
|---|---|
| mora_context | Сегодняшняя дата, счета и валюты, категории, бюджеты, цели и регулярные платежи |
| mora_preview_entries | Проверка пакета без записи |
| mora_add_entries | Атомарная запись расходов, доходов и переводов |
| mora_reassign_entries | Исправление счета существующих расходов и доходов с автоматическим пересчетом; сначала dry_run=true |
| mora_import_csv | Проверка и импорт CSV стандарта Mora |
| mora_create_account | Создание учетного счета с известным начальным остатком |
| mora_list_entries | Просмотр до 200 операций с фильтрами |
| mora_monthly_summary | Итоги месяца в валюте отчетов |
| mora_set_budget | Месячный лимит категории, включая изменение существующего лимита |
| mora_create_goal | Создание цели |
| mora_create_recurring | Создание расписания расхода без немедленного списания |

Денежные значения передаются строками. Счета и валюты обязательны, неизвестные счета не создаются молча. Новая категория требует allow_new_categories=true. У расходов и доходов передается исходная валюта: если она отличается от валюты выбранного счета, Mora автоматически получает курс Visa на дату операции и округляет до минимальной единицы валюты счета. Исходная сумма, валюта, курс и дата сохраняются в операции. При недоступном курсе пакет не записывается. У операций расход/перевод отрицательные, доход положительный. У расписаний расхода amount положительный. Лимиты бюджетов и суммы целей задаются в базовой валюте из mora_context.

Для каждой новой операции/пакета нужен уникальный request_id; при повторе того же пакета используйте тот же ID и порядок строк. Это сохраняет две реальные одинаковые покупки, но не создает дубликат при повторной доставке запроса. Если тот же ID использован с измененными данными, запись отклоняется. Для операций с банковским ID используйте поле id. Для CSV без ID действует сравнение содержимого, как в обычном импорте Mora.

Пакеты mora_add_entries и успешные импорты CSV с новыми операциями сохраняются в «Истории импортов» Mora 1.3; их можно отменить отдельно от остальных изменений. Повторный импорт без новых операций не создает пустую запись истории. Обновленный промпт требует уточнять неоднозначные или отсутствующие категории до записи. Перед использованием обновленного моста перезапустите Mora 1.4: старое открытое приложение не поддерживает новый формат данных. Последние 20 изменений, включая записи MCP, сохраняются с данными и доступны для отмены и возврата после перезапуска.

Счет существующих расходов и доходов исправляется через mora_reassign_entries с сохранением UUID, категорий и заметок и автоматическим пересчетом исходной суммы. Прочие изменения и удаления выполняются в интерфейсе Mora; исправление старой операции не следует записывать как новый расход.

## Streamable HTTP

Для MCP-клиентов с HTTP-подключением:
~~~sh
.venv/bin/python mcp/server.py --transport streamable-http --port 8765
~~~
Адрес: http://127.0.0.1:8765/mcp. Сервер создает случайный токен в ~/Library/Application Support/Mora/mcp-http-token с правами 0600 (для --data-dir — внутри выбранного каталога). В клиенте задайте заголовок Authorization: Bearer <значение файла токена>. Токен не входит в URL и не выводится в журнал. Режим без токена отсутствует; сервер слушает только 127.0.0.1, проверяет Host и Origin. При необходимости можно указать свой --token-file.

Для удаленного облачного AI-клиента localhost на вашем Mac недоступен. Ему требуется доступный HTTPS-адрес с подходящим для клиента способом авторизации; публичный сервер или туннель здесь не развернут. Клиентам, поддерживающим только OAuth-подключения, потребуется соответствующий шлюз авторизации. Сам протокол, инструменты и бизнес-логика одинаковы для всех клиентов.

Режим только чтения:
~~~sh
.venv/bin/python mcp/server.py --read-only
~~~

## Сохранность данных

Каждый запрос читает актуальную базу. Запись атомарная: неправильная строка отклоняет весь пакет. Перед изменением сохраняется штатная резервная копия ledger.json.backup. Межпроцессная блокировка и проверка ожидаемой версии предотвращают потерю изменений между GUI и MCP. После внешнего изменения старая история отмены очищается, чтобы Undo не удалил новые записи MCP; восстановление резервной копии доступно в настройках.

MCP не обращается к API моделей и не выбирает AI-провайдера. Он возвращает данные тому клиенту, который вы к нему подключили. Он ведет учет и не выполняет банковские платежи.

## Проверка

~~~sh
.venv/bin/python mcp/selftest.py
~~~
Проверка использует отдельную временную базу, официальный MCP-клиент, оба транспорта, схемы инструментов, prompts/resources, точные суммы, идемпотентность, ошибки и авторизацию. Временный HTTP-сервер завершается после проверки.

Также Swift-тесты проверяют CSV, валюты, конкурентную запись, защиту от устаревшего сохранения и финансовую бизнес-логику.
